## Overview

Implement classic partial order reduction to avoid exploring equivalent orderings during state space exploration. Two reconcilers that commute (no read/write overlap) don't need both orderings explored.

## Design Decisions

1. **Goal**: Soundness-preserving reduction - explore fewer orderings while guaranteeing all distinct converged states are found
2. **Commutativity detection**: Read/write set analysis at Kind level
3. **Granularity**: Kind-level (static) - simpler, can extend to object-level later
4. **Integration**: Filter at expansion time in `expandStateByReconcileOrder`
5. **Replaces**: Manual `PermuteOrder` config with derived commutativity analysis

## Core Data Structure

```go
// CommutativityManager determines which reconcilers commute based on static analysis
type CommutativityManager struct {
    // internal conflict graph (implementation detail)
    conflicts map[ReconcilerID]map[ReconcilerID]bool
    
    // cached read/write sets for debugging/inspection
    readSets  map[ReconcilerID][]string  // Kinds watched
    writeSets map[ReconcilerID][]string  // Kinds written
}

func (m *CommutativityManager) Commutes(a, b ReconcilerID) bool
func (m *CommutativityManager) MustOrder(a, b ReconcilerID) bool
func (m *CommutativityManager) ConflictsFor(id ReconcilerID) []ReconcilerID
```

## Conflict Rules

Two reconcilers A and B conflict (don't commute) if ANY of:
- `writes(A) ∩ reads(B) ≠ ∅`
- `writes(B) ∩ reads(A) ≠ ∅`
- `writes(A) ∩ writes(B) ≠ ∅`

## Static Analysis Pass

At startup, analyze each reconciler to extract:
- **Read set**: Kinds it watches (via `TriggerHandler.KindDepsForReconciler`)
- **Write set**: Kinds it creates/updates (needs new introspection from controller config)

Build internal conflict graph from these sets.

## Integration with Exploration

In `expandStateByReconcileOrder`:
- Before generating ordering variants, consult `CommutativityManager`
- Only generate variant orderings for reconciler pairs that conflict
- If `Commutes(A, B)` is true, don't bother generating [B, A, ...] when [A, B, ...] is default

## Future Extensions

- **Object-level commutativity**: Even if same Kind, different objects commute
- **Field-level commutativity**: Same object but different fields might commute
- **Validation mode**: Optionally verify commutativity assumptions at runtime
