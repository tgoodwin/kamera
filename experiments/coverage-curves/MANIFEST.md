# Paper Figure Manifest

Reproducibility map for the figures in the kamera paper (April 2026 submission).
For each paper figure, this file lists the script that produces it, the input
data files it consumes, and how those inputs were generated.

This is the **single source of truth for figure provenance**. If a file isn't
referenced here, it is not load-bearing for any published figure.

For experimental narrative (what the agent did, what the bug was, headline
numbers), see `summary.md` and the per-experiment `tuning-experiment-*.md` /
`*-tuning-log.md` files.

---

## Conventions

- All paths are relative to the repo root unless noted.
- "Per-iteration log" = the kamera simulator's structured JSON-lines stdout from
  one run of one tuned scenario variant. Each line carries
  `{"ts": ISO8601, "Total States": N, "# Distinct States": N, "Resource States": N, ...}`.
- "Accumulated log" = a preprocessed monotonic log built from raw evidence dumps
  when the underlying run had multiple phases that reset counters. Produced by
  the preprocessing block in `plot_exhaustive_vs_agent.sh`.
- "Padded log" = an agent log with a synthetic flat segment prepended to
  represent inference time before the agent's first scenario executed, so the
  agent and exhaustive curves share a `t=0`.

## Figure 8 — Exhaustive vs. Agent (3-panel: KCP4, KRO K2b, Karpenter D12)

**Artifact-evaluation driver:** `artifact/reproduce-figure8.sh`

The AE driver reruns all three fixed agent-selected simulations, checks their
observable outcomes, and extracts the exhaustive curves from checksummed raw
simulator-output archives under `artifact/data/figure8/raw/`. The extended
mode recomputes the exhaustive outputs as well. See
`artifact/figure8/README.md` for the packaging contract and source pins.

**Driver script:** `experiments/coverage-curves/plot_exhaustive_vs_agent.sh`
**Underlying plotter:** `scripts/plot_comparison.py`
**Output PDFs:**
- `kcp4-exhaustive-vs-agent.pdf` (paper) → mirrored to `kcp/k2b-exhaustive-vs-agent.pdf` is the KRO copy
- `k2b-exhaustive-vs-agent.pdf` → mirrored to `experiments/coverage-curves/kro/k2b-exhaustive-vs-agent.pdf`
- `d12-exhaustive-vs-agent.pdf` → mirrored to `experiments/coverage-curves/karpenter/d12-exhaustive-vs-agent.pdf`

The driver writes to `.worktrees/kamera-paper/papers/new/figures/` and copies
the KRO/Karpenter outputs back into `experiments/coverage-curves/<project>/`.

## Figure 2 — Agent Tuning Bars (per-iteration breakdown, 3-panel)

**Driver script (one shot, no args):** `experiments/coverage-curves/plot_tuning_bars.py`
**Output PDF:** `experiments/coverage-curves/tuning-bars.pdf`

Three side-by-side panels (KCP4 / KRO K2b / Karpenter D12). Each panel shows
per-iteration bars colored by reproduction status, with bar heights derived
from each iteration's per-iteration log.

| Panel | Inputs (per-iteration logs `v{1..N}-log.txt`) | Reproduction status (hard-coded in script) |
|---|---|---|
| KCP4 | `experiments/coverage-curves/kcp/relaxed-tuning/trial2-final/kcp4-trial2-v{1..10}-log.txt` | v1-v4 yes, v5 no, v6 no, v7 yes, v8 no, v9 yes, v10 no |
| KRO K2b | `experiments/coverage-curves/kro/tuning-runs/k2b-tuning-v{1..10}-log.txt` | v1-v9 yes, v10 no |
| Karpenter D12 | `experiments/coverage-curves/karpenter/tuning-runs-v2/d12-tuning-v{1..14,final}-log.txt` | (see top of `plot_tuning_bars.py` for the `d12_repro` map) |

**Provenance of each tuning-runs directory:**
- KCP4 (`kcp/relaxed-tuning/trial2-final/`) — driven by the v2 ("relaxed") agent
  prompt template `experiments/coverage-curves/tuning-agent-prompt-v2.md`. Per-iteration
  narrative in `kcp/relaxed-tuning/trial2-final/log.md`. **This is the
  authoritative KCP tuning data**; everything in `kcp/tuning-runs-old/` is from
  the v1 prompt and is superseded.
- KRO K2b (`kro/tuning-runs/`) — driven by `kro/tuning-agent-prompt-kro-k2b.md`
  (an adaptation of v2 for fault-injection bugs). Narrative in
  `kro/tuning-experiment-k2b-log.md`.
- Karpenter D12 (`karpenter/tuning-runs-v2/`) — driven by
  `karpenter/tuning-agent-prompt-d12.md`. Narrative in
  `karpenter/tuning-runs-v2/d12-tuning-v2-log.md`. The earlier
  `karpenter/tuning-runs/` (v1, no `-v2` suffix) is **superseded** by v2 and not
  used by any paper figure.

## Raw evidence dirs (large, regenerable, not directly plotted)

These are the harness output directories that the preprocessing step in
`plot_exhaustive_vs_agent.sh` reduces to the `*-accumulated.txt` files. They
are **not directly read by any plotting script**; only the preprocessing step
needs them, and only when re-running with `--preprocess`.

| Dir | Size | What it is | Required for paper figures? |
|---|---|---|---|
| `experiments/coverage-curves/karpenter/exhaustive-output/` | ~798 MB | 1,214 JSONL phase dumps + per-child staleness CSVs from the D12 exhaustive sweep | Only if regenerating `d12-exhaustive-accumulated.txt` |
| `experiments/coverage-curves/kro/k2b-exhaustive-output/` | ~35 MB | 30 JSONL reference/rerun dumps plus 1,680 metrics-only staleness rows from the 15-entry K2b matrix (anchor 2026-03-30T14:35:31-07:00) | Only if regenerating `k2b-exhaustive-accumulated.txt` |
| `experiments/coverage-curves/kro/k2b-exhaustive-output-7ctrl-permute/` | ~534 MB | Alternative K2b sweep with 7 controllers permuted (cross-check, not in paper) | No |

To regenerate exhaustive evidence dirs from scratch, see the harness invocation
in `karpenter/README.md` (Karpenter) or run the corresponding scenario via the
KRO harness with `--output <evidence-dir>`.
