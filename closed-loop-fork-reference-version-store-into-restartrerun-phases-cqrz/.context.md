## Context
Closed-loop restart/rerun execution hit a state-store mismatch when history prefixing was enabled.

Observed behavior before the fix:
- Reference run completed and wrote a dump.
- Rerun often failed to write a dump (especially in `--parallel-processes` mode) with:
  `unable to resolve object for hash ...`

Repro command used:
`go run . --inputs /tmp/knative-one.json --dump-output /tmp/knative-dumps --depth 100 --timeout 60s --dump-stats /tmp/knative-stats`

What was happening:
- Rerun phases used `HistoryPrefix` from reference execution.
- Prefix steps referenced historical object hashes that existed in the reference run's version store.
- The rerun phase store initially contained only seeded checkpoint/current state, not full prefix history hashes.
- Dump writing resolves hashes for full path history and failed on missing prefix hashes.

Current stopgap behavior:
- We added priming logic that materializes referenced prefix hashes into rerun phase stores so dumps succeed.
- This fixes the immediate failure but preserves an indirect coupling path.

## Proposed Fix (Option 1)
Adopt an explicit "store fork" model for restart/rerun phases:
- Build rerun phases from a cloned/forked snapshot of the reference run version store.
- Treat restart runs as a child continuation of the reference store lineage, instead of reconstructing needed hashes ad hoc.
- Keep `RestartSeed`/`HistoryPrefix` semantics unchanged, but make backing object resolution guaranteed by construction.

Why this is cleaner:
- Removes implicit dependency on post-hoc hash priming.
- Makes state lineage explicit and easier to reason about.
- Reduces risk of future missing-hash failures when prefix behavior evolves.

## Scope
- Introduce a first-class store fork/clone handoff at reference -> rerun boundary.
- Use forked store for all prefixed restart phases.
- Retain existing closed-loop v0 behavior and APIs.
- Keep output artifacts unchanged (reference/rerun dumps + stats).

## Acceptance Criteria
- Repro command above consistently writes both `reference` and `rerun` dumps.
- `--parallel-processes` mode also writes both dumps without hash resolution failures.
- `RestartSeed` + `HistoryPrefix` path exercises continue to work with no priming-specific code path required.
- Regression test(s) cover prefixed rerun dumpability under forked-store design.
- No external CLI/API changes required for users.
